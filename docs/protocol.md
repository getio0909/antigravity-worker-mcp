# MCP protocol

The stdio server exposes eight tools. Control responses use a stable JSON envelope generated by the wrapper. Agent answers are ordinary text; the wrapper does not require a report schema or parse the answer to decide whether execution succeeded.

## ag_submit

Only instructions is required:

```json
{
  "instructions": "Inspect this project and explain how it works."
}
```

The instructions string goes to the official CLI unchanged. No task classification, report instructions or evidence requirements are appended. The default working directory is the MCP connection's current directory, captured before its background supervisor starts. Supply an absolute root when the project directory matters.

```json
{
  "instructions": "Implement the change and run the relevant checks.",
  "root": "/absolute/path/to/project",
  "model": "A_NATIVE_SLUG_FROM_AGY_MODELS",
  "idempotency_key": "change-001"
}
```

| Parameter | Behavior |
| --- | --- |
| instructions | Required task text, 1–16,000 Unicode characters. |
| root | Optional absolute working directory; defaults to the submitting MCP connection's cwd. |
| model | Optional native CLI model slug; overrides model_profile. |
| model_profile | Optional fast or deep configured profile; defaults to fast. No silent model substitution. |
| kind | Optional arbitrary label for status metadata. It never changes the task or CLI behavior. |
| isolation | False by default. True selects a Linux working copy. |
| execution_mode | Host by default; optional workspace or read-only analysis. |
| files | Optional selected UTF-8 files for capture or isolated execution; no recursive expansion. |
| timeout_seconds | Zero disables the deadline. Omitted or null uses timeoutSeconds, default zero. |
| idempotency_key | Optional retry key, 1–128 UTF-8 bytes. Identical retries return the original job. |

A missing or empty allowedRoots list permits any existing working directory accessible to the current user. An explicit nonempty list restricts the initial directory to exact canonical matches. It does not restrict later host commands.

Submission returns job_id, state, execution_mode, deadline, background, supervisor_ready, deduplicated and result_expired. A disabled deadline is null. Timestamps use Unix milliseconds. Deadlines include queue time and have no 900-second cap.

The same key and task parameters return the same ID, including after failure or result disposal. Different parameters return IDEMPOTENCY_CONFLICT. Failed or interrupted work is never automatically replayed.

## ag_status

Input: `{ "job_id": "uuid" }`.

States are queued, running, cancelling, completed, failed and cancelled. Progress contains events, steps and output_bytes; these are counts, not tool-call totals or a percentage.

Completed means that the CLI returned SUCCESS and exited with code zero, and wrapper execution/storage finished. It does not certify the answer or host effects. Recovered tool errors and permission diagnostics do not override a successful terminal CLI result.

Jobs survive client disconnects. Clients sharing the same private stateDirectory can discover, query and cancel them. A lost supervisor is reported as RUNNER_INTERRUPTED without replay.

## ag_result

```json
{
  "job_id": "uuid",
  "section": "response",
  "offset": 0,
  "limit": 8000
}
```

The text field contains a page of the original CLI response. Plain text, Markdown, code, JSON, whitespace and Unicode are preserved. There is no required summary, findings, limitations, severity or evidence shape. The wrapper neither rewrites the answer nor treats body formatting as execution failure.

Section is response or patch. Offset counts Unicode characters. Limit defaults to 8,000 with a maximum of 16,000. Follow next_offset until null to retrieve the complete content. A pending job returns ready: false.

Terminal metadata includes state, completion, verification_status, selected and actual models, cli_status, usage when available, error, exit_code, duration_ms, audit references, input manifest, page information, patch availability/truncation and expiry. Deprecated report-preview fields are absent in version 0.3.

Completed results remain verification_status: unverified. Host agents interpret the native answer and inspect any changes. A response can legitimately be empty. Patch truncation does not certify an applicable complete patch.

Default results do not expire. Positive retentionSeconds starts expiry after completion. ag_forget frees result capacity but preserves status, retry keys and enabled audit logs. Results from earlier versions remain readable as their stored text; their historical states and errors are not silently rewritten.

## ag_cancel

Input: `{ "job_id": "uuid" }`.

Queued jobs cancel without inference. Running jobs request cancellation and wait up to ten seconds for supervised cleanup. If cleanup is pending, inspect process_stopped and poll ag_status. Completed terminal results win over late cancellation. Cancellation does not reverse existing host changes or external effects.

## ag_capabilities

Input: `{}`.

Query the CLI version and native model catalog without inference. The response includes configured profiles, execution modes, default lifetime, audit settings and resource bounds. Version 0.3 adds response_format: native_text, task_instructions: unchanged and root_allowlist_enabled.

Remaining subscription quota is unavailable. Reported token usage is not converted into estimated remaining allowance.

## ag_list, ag_resume and ag_forget

ag_list accepts optional after and limit, default 20 and range 1–50. It returns newest-first job metadata and next_after, without task text.

ag_resume clears a shared quota pause. Queued jobs can then proceed; failed tasks are not retried. Check actual provider availability before resuming.

ag_forget accepts a job ID and discards a terminal answer or patch. Metadata, retry keys and enabled audit logs remain. Active jobs return JOB_ACTIVE. Capacity exhaustion returns RESULT_STORE_FULL rather than silently deleting retained work.

## Native CLI framing

The adapter uses the official stream-json input/output framing to capture progress, tools and a terminal result. This framing does not constrain the model's answer. The adapter does not pass --json-schema.

All modes pass --dangerously-skip-permissions and --mode accept-edits. Unlimited tasks use --print-timeout 0. Only isolated requests disable slash commands. Host mode inherits the CLI's existing configuration.

The parser observes init, step_update and one terminal result; unknown event types are ignored. Malformed framing, duplicate results, failed terminal CLI status, nonzero exit, cancellation, deadlines and operational storage failures remain explicit errors. Individual NDJSON events are bounded at 2 MiB; there is no cumulative task-stream cap.

These transport/resource bounds apply to wrapper operation. They are not a host command policy or a required answer format.
